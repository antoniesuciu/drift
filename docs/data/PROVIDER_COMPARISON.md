# MES historical-data provider decision

Reviewed **2026-10-29** using public primary documentation only. No account was opened, provider cost API called, broker connected, sample/data downloaded or purchase made. Advertised coverage and documented semantics are distinguished from **unverified** contract-level completeness, account entitlements and request-specific prices. Dataset scope is owned by [HISTORICAL_DATA_SPEC.md](HISTORICAL_DATA_SPEC.md); M2b behavior and gates belong to [INGESTION_DESIGN.md](INGESTION_DESIGN.md).

M2b.2's [vendor verification](M2B2_VENDOR_VERIFICATION.md) updates public pricing/rights evidence, including optional Standard L0 history and the distinction between free metadata queries and billable definition time series. The [market verification](M2B2_MARKET_VERIFICATION.md) and [nine-job acquisition plan](M2B2_ACQUISITION_PLAN.md) record historical-calendar/metadata limits and exact proposed request bounds. Exact pilot/archive totals and applicable Databento retention rights remain unresolved; no account query or acquisition occurred.

## Recommendation and reason

**Recommend Databento historical usage-based `GLBX.MDP3` for the multi-year MES study**, initially minute OHLCV plus actual-contract definitions/mappings, conditional on the exact quote, license/retention review and contract coverage checks below. Keep IBKR as the selected eventual paper broker and a possible recent-history cross-check. **FirstRate Data individual MES contracts are the principal lower-complexity bar-only alternative** if its actual purchase quote and supplemented metadata make it preferable. No recurring live-data plan is selected or necessary merely to design this archive.

This is an engineering recommendation, not a measured assertion that one vendor's prices are more accurate. It follows from an evidenced IBKR archive limitation, Databento's metadata and schema support, and a release-specific Nautilus integration. It implements the existing IBKR-first feasibility decision: IBKR was evaluated first and cannot now supply the complete 2020–2025 expired-contract study. It does not make Databento a mandatory platform dependency or authorize spending. A cheaper verified equivalent can replace it without changing the normalized schema.

### Timestamp and missing-record differences

| Provider | Documented representation | Required normalization/check |
|---|---|---|
| IBKR | Epoch seconds with `formatDate=2`; string dates can depend on configured operator, instrument or UTC timezone. Ongoing historical-bar updates can repeat an unfinished bar timestamp. | Use explicit UTC/epoch requests, actual contract details and completed one-shot data. Verify the selected adapter's bar boundary labeling against a known fixture; the cited generic API page does not prove every adapter's start/end convention. [Date format](https://www.interactivebrokers.com/docs/tws-api/doc/tws-settings/historical-date-format), [request parameters](https://www.interactivebrokers.com/docs/tws-api/sync-doc/historical-market-data). |
| Databento | Raw OHLCV `ts_event` is the **inclusive interval start**, with aggregation based on trade `ts_recv`; no record is emitted for a no-trade interval. | Raw 09:59 minute represents the interval ending 10:00. Preserve source labels and aggregation basis; model completion/availability separately. A bar has no observed strategy-receipt timestamp merely because its record is historical. [OHLCV schema](https://databento.com/docs/schemas/ohlcv). |
| FirstRate | Intraday labels mark bar start in US Eastern, EST/EDT as appropriate; no-trade intervals are omitted. Daily futures close is settlement rather than the last intraday trade. | Localize to `America/New_York` with explicit ambiguity/nonexistent-time handling, then convert to UTC and add interval duration once. Do not use a daily settlement as the prior 16:00 observation or forward-fill an absent endpoint. [FAQ, Data Format/Futures](https://firstratedata.com/about/faq). |

Absence of a record is not sufficient to distinguish a genuine no-trade minute from delivery loss. Provider quality/status evidence and adjacent-session checks must classify the gap; unexplained gaps remain quarantined. Historical file acquisition time, source event/capture time and modeled decision availability are separate fields.

### NautilusTrader 1.231.0

The [tagged Databento guide](https://github.com/nautechsystems/nautilus_trader/blob/v1.231.0/docs/integrations/databento.md) documents DBN loading, historical queries, instrument definitions and OHLCV decoding. It describes a statically linked Rust client, so that integration does not itself require installing a separate Python `databento` SDK. Exact installed-wheel symbols/DBN compatibility remain an M2b offline fixture gate.

The decoder normally shifts raw bar timestamps to interval close; `bars_timestamp_on_close` controls this behavior. Historical/file `ts_init` can default to close. Thus M2b must **avoid double-shifting** and explicitly apply the chosen modeled availability delay. Venue mapping can use `GLBX` or exchange MICs such as `XCME`; map this deliberately to the project's canonical contract key, not by string assumption. Reuse supported loaders and Parquet catalog functionality where the pinned release passes tests. FirstRate CSVs require a thin normalization path rather than a new engine; the [tagged IB guide](https://github.com/nautechsystems/nautilus_trader/blob/v1.231.0/docs/integrations/ib.md) supports future approved IB access. No adapter was exercised on vendor market data in M2a.

## Licensing and local retention

- **Databento:** historical service documentation distinguishes historical from real-time licensing; this does not grant unrestricted redistribution or prove perpetual post-termination retention. Publisher-specific terms still apply. Obtain the applicable CME historical agreement and confirm local raw/Parquet/cache/backups, research/model use, retention after cancellation, and derived-output rights before acquisition. Public general terms were not sufficiently accessible to establish these points; mark them unresolved. [Service distinction](https://databento.com/docs/quickstart/choose-service), [licensing explanation](https://databento.com/blog/introduction-market-data-licensing), [terms entry point](https://databento.com/legal).
- **FirstRate:** the public license expressly permits perpetual storage/use on the subscriber's own servers and database import, while restricting raw-data redistribution and governing team/service-provider use. It permits derivative works; full license wording takes precedence over abbreviated FAQ wording. Provide attribution when publishing under the full agreement. Purchased access/download links can expire even though permitted local use continues. [Full license](https://firstratedata.com/about/license).
- **IBKR:** API availability is not a separate grant of archive/publication rights. Review the actual entity's market-data/user agreements and provider conditions for local retention, backups and derived use; no blanket perpetual-storage or redistribution right is asserted. [Market-data account requirements](https://www.interactivebrokers.com/en/pricing/market-data-pricing.php).
- **CME DataMine:** retain the applicable Information License Agreement and dataset-specific use/retention conditions. Publisher-direct acquisition is not an automatic waiver of restrictions. [DataMine](https://www.cmegroup.com/datamine.html).

For every option, keep vendor data and account/license records out of Git/Obsidian. Store a non-sensitive rights summary, agreement version/date and approval reference in dataset provenance; keep confidential agreements elsewhere. Raw data remains local and access-controlled, including backups. Do not send it to external LLM services or publish it under the repository's code license.

## Exact quote and acceptance request for M2b

After explicit acquisition authorization, obtain the following information **before downloading**:

1. Freeze the [historical specification](HISTORICAL_DATA_SPEC.md)'s minimum pipeline sample separately from the 2020-01-02 through 2025-12-31 study, including the 2019-12-31 previous full session's 16:00 observation and roll-overlap buffers. The development-only pilot covers 2022-03-07..03-25 and 2022-11-21..12-02, with acquisition buffers `[2022-03-04, 2022-03-26)` and `[2022-11-18, 2022-12-03)` in UTC. These 2022 windows are also outside IBKR's current expired-contract limit; a recent IBKR engineering sample cannot replace this pilot. Preserve the 2024–2025 holdout.
2. Databento: `GLBX.MDP3`, `ohlcv-1m`, actual dated **MES outright futures** selected by the manifest: 25 quarterlies MESH20 through MESH26 for the full study, and MESH22/MESM22/MESZ22 for the pilot, plus historical `definition`/symbol mappings and any justified status records. Request only each contract's required windows, prior-close/roll buffers; exclude options/spreads, `ALL_SYMBOLS`, deep-book schemas and unrelated exchange products. Obtain a base minute quote separately from optional trade/BBO execution-quality extensions.
3. Request record/byte estimates, exact all-in USD/local-currency amount, tax/fees, quote date/expiry, redownload/retry billing, license/retention requirements and spending ceiling. Do not substitute an empty calculator default, another product's estimate or monthly live price.
4. FirstRate alternative: confirm initial tax-inclusive local purchase price, exact individual-contract coverage before/after each roll (especially the year-end input), historical corrections, available contract map and missing metadata supplementation. Use downloaded individual contracts; do not inherit undocumented continuous-series roll/adjustment rules.
5. Release acquisition only when both rights and cost are approved. Then prove every requested contract/session is present or explicitly excluded, test endpoint/no-trade/corruption cases, record excluded-session counts and preserve immutable raw hashes. Current public evidence does not satisfy that delivered-data gate.

Open questions are precise, not implicit defaults: exact MES coverage/quality matrix; acquisition quote; Databento/IBKR retention terms; actual account rights; source definition/ID mapping completeness; acceptable realized sample loss; and whether quote/trade data are needed for the later cost-sensitive validation. The recommended provider can change if these gates reject it. M2b implementation/acquisition has not begun.
